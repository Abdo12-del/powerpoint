# 📋 التقرير الشامل: هيكل العرض التقديمي القياسي (Presentation Template Spec)

> **الغرض**: أن يقرأه أي وكيل (Agent) فيحوّل **أي مشروع محتوى** (مذكرة، دورة، تقرير، منتج، دراسة حالة) إلى **عرض تقديمي مهيكل** — بنفس التسلسل الذي يستخدمه هذا القالب في المستودع. التقرير يصف **البنية والتدفق وتشريح الشريحة ووصفة التقسيم** — بعيداً عن الألوان والزخارف.

> **خريطة التنفيذ في هذا المستودع** (كل فقرة من المواصفة لها ملف يطبّقها):
>
> | الفقرة | الملف |
> |---|---|
> | §2 الشاشات الثابتة | `src/components/screens/{Title,Preface,Map,Slide,Final}Screen.tsx` |
> | §3–§4 عقود الفصل والشريحة | `src/types/presentation.ts` |
> | §5 الأنماط العشرة | `src/components/archetypes/` (المرجع: [`ARCHETYPES.md`](./ARCHETYPES.md)) |
> | §6 التدفق والتحكم | `src/lib/navigation.ts`، `src/hooks/usePresentation.ts`، `src/config/controls.ts` |
> | §7 الاستمارة الفارغة (تُملأ لكل عرض) | `src/data/presentation.tsx` + `src/data/chapters/ch1..ch3.tsx` |
> | §9–§10 قواعد الحماية وقائمة التحقق | `src/lib/validate.ts` + `src/__tests__/` |

## 1. الفكرة الجوهرية

أي عرض تقديمي ناجح هو **هرم من 4 مستويات**، لا صفحات متفرقة:

```
العرض (Presentation)
├── شاشات ثابتة (Fixed Screens): العنوان ← المقدمة ← الخريطة ← الخاتمة
└── الفصول (Chapters)
    └── الشرائح (Slides)
```

**القاعدة**: المحتوى الخام للمشروع (نصوص، بيانات، صور) لا يُعرض مباشرة — يُمرَّر عبر **معمل التقسيم**: مشروع → فصول → محاور → شرائح → كتل محتوى داخل كل شريحة.

---

## 2. المستوى الأول: الشاشات الثابتة (ترتيب إلزامي)

كل عرض يمرّ عبر **5 شاشات بهذا الترتيب بالضبط**:

### 2.1 شاشة العنوان (Intro / Title)
أول ما يراه المشاهد. تحتوي **بطاقة تعريف العرض**:

| العنصر | الوصف | مثال تعبئة |
|---|---|---|
| الجهة الرسمية | الدولة/الوزارة/المؤسسة | «الجمهورية الجزائرية…» |
| نوع العمل | طبيعة المشروع | «مذكرة تخرج» / «تقرير سنوي» |
| **العنوان الرئيسي** | جملة واحدة تصف المشروع | «تصميم نظام معلوماتي لتسيير…» |
| العنوان الفرعي | توضيح أو مكان التطبيق | «دراسة تطبيقية بـ…» |
| المُنجزون | الأسماء + الأدوار | «إعداد: … / إشراف: …» |
| التاريخ/الدفعة | | |
| **زر البدء** | الدعوة للانتقال | «اضغط للبدء» |

*لا يوجد محتوى تعليمي هنا — هوية فقط.*

### 2.2 المقدمة (Preface) — 3 إلى 4 خطوات
تُقدَّم كـ **خطوات متتابعة** (كل خطوة شريحة كاملة):
1. **تمهيد عام**: لماذا هذا الموضوع مهم؟ (سياق 2–3 جمل)
2. **الإشكالية/المشكلة**: ما العجز أو الحاجة؟ تُصاغ كسؤال واحد واضح: «كيف يمكن…؟»
3. **الأهداف**: 4–6 أهداف بصيغة مفعول بها («أتمتة…»، «تقليل…»، «تسهيل…»)
4. **النطاق/المنهجية** (اختياري): أين طُبّق؟ بأي طريقة (MERISE، Agile…)؟

### 2.3 خريطة الفصول (Map / Agenda)
شاشة وسطى تعرض **كل الفصول وكل محاورها كعقد مرئية** — تعمل كخريطة تنقّل:
- اختيار أي محور → يقفز مباشرة إلى شريحته
- العودة من أي شريحة → الخريطة (تظهر الفصل الحالي كمُميَّز)

*هذه الشاشة تُبنى آلياً من مصفوفة الفصول — لا يُكتب لها محتوى يدوياً.*

### 2.4 الشرائح (Slides) — المحتوى الفعلي (§3 و§4)

### 2.5 الخاتمة النهائية (Final)
شريحة أو شريحتان: **خلاصة العرض في 3–4 جمل** + نتيجة/دعوة تأمل + شكر/أسئلة. لا معلومات جديدة إطلاقاً.

## 3. المستوى الثاني: الفصول (Chapters)

كل فصل = **وحدة سردية مغلقة** بعنوان يجيب عن سؤال واحد من الإشكالية.

| القاعدة | التفصيل |
|---|---|
| عدد الفصول | **3 إلى 5** — أقل من 3 ضحل، أكثر من 5 متشتت |
| تدرّج الفصول | يُرقم ويُسمّى بأسماء معرفية: «الدراسة التمهيدية»، «الدراسة التفصيلية»، «الدراسة التقنية» |
| شريحتا الحصر | كل فصل **يفتتح بـ«تمهيد الفصل»** (جملة انتقال) و**يُختتم بـ«خلاصة الفصل»** (3–5 نقاط) |
| التماسك | كل شريحة داخل الفصل تحمل `chapterId` الخاص به |

**البنية النموذجية لفصول مذكرة/دراسة** (قابلة للتكييف):
```
الفصل 1 — الدراسة التمهيدية: من نحن؟ ما المشكلة؟ (تعريف، تنظيم، مسح، نقد)
الفصل 2 — الدراسة التفصيلية/التصميم: ما الحل؟ (بيانات، نماذج، قواعد)
الفصل 3 — الدراسة التقنية/التنفيذ: كيف نُنجز؟ (أدوات، واجهات، حماية)
```

## 4. المستوى الثالث: تشريح الشريحة (Slide Anatomy)

كل شريحة = كائن بهذا العقد (مطابق لـ `SlideData` في `src/types/presentation.ts`):

```ts
interface SlideData {
  id: string;               // معرف فريد ببادئة الفصل: "ch1-procedures"
  chapterId: string;        // الفصل المالك
  title: string;            // عنوان قصير (3–6 كلمات) — يظهر في رأس الشريحة
  subtitle?: string;        // توضيح في سطر واحد (اختياري)
  icon: LucideIcon;         // أيقونة تدل على نوع المحور (تظهر في الخريطة)
  archetype: SlideArchetype;// النمط المعياري (§5) — يُحدَّد قبل كتابة المحتوى
  content: ReactNode;       // كتل المحتوى (§5)
  notes?: string;           // ملاحظات المُقدِّم (لا تُعرض)
}
```

**قواعد العنوان**: اسم وليس جملة («دراسة الوثائق» لا «في هذا الجزء سندرس الوثائق»)؛ لكل شريحة **فكرة مركزية واحدة** فقط؛ إن تعذّرت في سطر واحد فالمحتوى يحتاج شريحتين.

**قواعد المحتوى داخل الشريحة**:
- لا تتجاوز 5–6 كتل (بطاقات/نقاط) في شريحة واحدة
- النقطة: جملة واحدة ≤ 12 كلمة
- كل رقم أو مصطلح تقني يُبرز (شارة/كود)، ولا يُكتب في نص سائب — في الكود: `<Num>`، `<Term>`، `<Badge>`
- المقارنات والمخططات تُقدَّم كعناصر بصرية (§5) لا كفقرات

## 5. أنماط الشرائح المعيارية (Slide Archetypes)

أي محتوى يُلبَّس أحد هذه الأنماط — **10 أنماط تغطي 95% من أي مشروع**:

| النمط | `archetype` | المكوّن | متى يستعمل | شكل المحتوى الداخلي |
|---|---|---|---|---|
| **1. بطاقة تعريف** | `profile` | `ProfileCard` | تعريف مؤسسة/منتج/شخص | بطاقة كبيرة + 3–4 حقائق جانبية |
| **2. قائمة نقاط** | `bullets` | `BulletCards` | الأهداف، المزايا، العيوب | 4–6 بطاقات/نقاط |
| **3. خط زمني** | `timeline` | `Timeline` | التاريخ، المراحل، الإصدارات | سنوات/محطات على خط (أفقية أو رأسية) |
| **4. هيكل شجري** | `tree` | `OrgTree` | التنظيم، التسلسل الإداري | عقد + موصلات (مدير ← مصالح ← أدوار) |
| **5. مقارنة زوجية** | `comparison` | `Comparison` | مشكلة↔حل، قبل↔بعد | صفين متقابلين + سهم/فاصل بينهما |
| **6. سير إجراء** | `process` | `ProcessFlow` | خطوات عملية، workflow | خطوات مرقّمة على مسار (1 → 2 → 3…) |
| **7. جدول/بطاقات بيانات** | `table` | `DataTable` | قاموس المعطيات، المقارنات الكمية | جدول أو بطاقات بحقول مسمّاة |
| **8. مخطط علائقي** | `relation` | `RelationDiagram` | MCD، ER، المخططات | كيانات + خطوط ربط + تسميات (1,n) |
| **9. كود/نموذج تقني** | `code` | `CodeBlock` | MLD، SQL، أمثلة شفرة | نافذة كود بعناوين أسطر |
| **10. إحصائيات/مؤشرات** | `stats` | `StatCounters` | الأرقام، الحصائل | عدّادات + أيقونات + وسوم |

وشريحتا الحصر: `chapter-preface` → `ChapterPreface`، و`chapter-summary` → `ChapterSummary`.
وقيمة مؤقتة `placeholder` → `<Placeholder />`: شريحة لم تُصنَّف بعد (يأتي بها القالب الفارغ، ويحذّر منها التحقق حتى تُستبدل).

**القاعدة**: كل شريحة في المشروع تُصنَّف أولاً إلى أحد الأنماط العشرة، ثم تُبنى — هذا يمنع التكرار ويجعل الهيكل متوقّعاً لأي وكيل.

## 6. تدفق العرض (Flow + التحكم)

```
العنوان ─(ابدأ)─▶ المقدمة (خطوات) ─(التالي)─▶ الخريطة ─(اختيار محور)─▶ الشريحة
   ▲                  │                        ▲ ▼                          │
   └────(العودة)──────┘                        └───────(الخريطة/Esc)────────┘
                                                   (Esc من الخريطة) ─▶ القائمة/الخروج
```

**عقد التحكم الإلزامي** في أي تنفيذ:
- `→` / `Enter` / `Space`: شريحة تالية | `←`: السابقة
- `↓` / `m` / `Esc`: الخريطة | `F`: ملء الشاشة
- شريط تقدّم أعلى الشاشة (عرضه = الموضع/الإجمالي)
- عدّاد «الشريحة 5 / 22» في شريط التحكم
- تنقل بالفأرة/اللمس (أزرار + بطاقات الخريطة قابلة للنقر)

> في هذا التنفيذ تُقرأ خريطة المفاتيح من `src/config/controls.ts` (مع دعم الأحرف العربية المقابلة: `ة` للخريطة، `ب` لملء الشاشة)، ويُضاف `?` لنافذة الاختصارات، والسحب يميناً/يساراً للمس.

## 7. الوصفة: تحويل أي مشروع إلى هذا الهيكل (7 خطوات للوكيل)

**الخطوة 1 — استخراج الهيكل العظمي**: اقرأ المشروع واسأل: «ما الأسئلة الثلاثة إلى الخمسة التي يجب أن يجيب عنها العرض؟» كل سؤال = فصل.

**الخطوة 2 — تقسيم كل فصل إلى محاور**: لكل فصل 4–8 محاور؛ كل محور = شريحة. إن تجاوز المحور 6 كتل محتوى → قسّمه إلى شريحتين.

**الخطوة 3 — تصنيف كل شريحة**: اختر لها نمطاً من العشرة (§5) — هذا يحدد شكل `content` تلقائياً.

**الخطوة 4 — كتابة الأغلفة النصية**: لكل شريحة: `title` (اسم موجز) + `subtitle` (اختياري) + أيقونة دالة.

**الخطوة 5 — بناء الشاشات الثابتة**: العنوان (§2.1) ← المقدمة كخطوات (§2.2) ← الخاتمة (§2.5) + شريحتا «تمهيد» و«خلاصة» لكل فصل.

**الخطوة 6 — التحقق من التوازن**: تدرّج المفاهيم من العام إلى الخاص؛ كل فصل يُبنى على ما قبله؛ الخلاصات تجيب عن سؤال الفصل.

**الخطوة 7 — التمثيل بالبيانات** (العقد الأدنى — ملف `src/data/chapters/ch1.tsx`):

```tsx
export const ch1: ChapterData = {
  id: 'ch1',
  title: 'الدراسة التمهيدية',
  subtitle: 'من نحن؟ وأين تكمن المشكلة؟',
  icon: Layers,
  color: 'from-blue-600/20 to-blue-400/20',
  accent: 'text-blue-200 border-blue-400/40',
  slides: [
    { id: 'ch1-preface', chapterId: 'ch1', title: 'تمهيد الفصل الأول', icon: Info,
      archetype: 'chapter-preface', content: <ChapterPreface number={1} lead="…" question="…" outline={[…]} /> },
    { id: 'ch1-profile', chapterId: 'ch1', title: 'التعريف بالمؤسسة', icon: Building2,
      archetype: 'profile', content: <ProfileCard name="…" description="…" facts={[…]} /> },
    // ... حتى الخلاصة
    { id: 'ch1-conclusion', chapterId: 'ch1', title: 'خلاصة الدراسة التمهيدية', icon: CircleCheck,
      archetype: 'chapter-summary', content: <ChapterSummary points={[…]} /> },
  ],
};
```

ثم تُجمَّع الفصول في `src/data/chapters/index.ts`، وتُربط مع `meta` و`preface` و`final` في `src/data/presentation.tsx`.

> **القالب يأتي فارغاً**: ملفات `src/data/` هي استمارات بنصوص نائبة وشرائح `placeholder`. عند بدء عرض جديد تُستبدل النصوص وتُستبدل كل `<Placeholder />` بمكوّن النمط المناسب؛ تقرير التحقق في وحدة التحكم يعدّد الشرائح التي ما تزال فارغة.

## 8. مثال مكتمل التعبئة (مشروع وهمي: «تقرير تحسين مطعم»)

مثال توضيحي للتقسيم فقط — **غير مضمَّن في الكود** لأن القالب يأتي فارغاً:

```
العنوان: دراسة تحسين أداء مطعم «النخيل» — دفعة 2026
المقدمة: (1) سياق قطاع المطاعم (2) الإشكالية: بطء الخدمة وتذبذب الجودة (3) الأهداف: رفع الرضا، تقليل الهدر (4) المنهج: مسح ميداني + تحليل

الفصل 1 — الدراسة التمهيدية
  • تمهيد الفصل
  • التعريف بالمطعم (نمط 1: بطاقة تعريف)
  • الهيكل التنظيمي (نمط 4: شجري)
  • مسح الخدمات الحالية (نمط 2: نقاط)
  • سير الطلب الحالي (نمط 6: سير إجراء)
  • الإشكاليات الميدانية والحلول (نمط 5: مقارنة زوجية)
  • خلاصة الفصل

الفصل 2 — الدراسة التحليلية
  • تمهيد الفصل
  • مؤشرات الأداء الحالية (نمط 10: إحصائيات)
  • تدفق الطلبات في وقت الذروة (نمط 3: خط زمني)
  • قاموس المعطيات (نمط 7: جدول)
  • النموذج المفاهيمي للبيانات (نمط 8: مخطط علائقي)
  • مراحل التحسين المقترحة (نمط 3: خط زمني رأسي)
  • خلاصة الفصل

الفصل 3 — خطة التنفيذ
  • تمهيد الفصل
  • التقنيات المستخدمة (نمط 7: جدول)
  • النموذج المنطقي للبيانات (نمط 9: كود SQL)
  • لوحة المتابعة والأهداف (نمط 10: إحصائيات)
  • الأمن وجودة الخدمة (نمط 2: نقاط)
  • خلاصة الفصل

الخاتمة النهائية (خلاصة عامة + دعوة تأمل + شكر)
```

## 9. قواعد مانعة للخطأ (Agent Guardrails)

1. **فكرة واحدة لكل شريحة** — «إن لم تستطع صياغة العنوان في 6 كلمات فأنت تجمع شريحتين».
2. **لا مفاجآت في الخاتمة**: الخاتمة تلخّص ولا تُدخل معلومة جديدة.
3. **الإشكالية كسؤال واحد** — كل فصول العرض يجب أن تبدو كإجابات جزئية عليه.
4. **أرقام ومصطلحات مُبرَزة** في عناصر بصرية (عدّاد، شارة، كود) لا داخل فقرات.
5. **العناوين العربية**: نص عادي دائماً — **لا تقسم النص العربي إلى حروف** في أي أنيميشن (يُقسَّم بالكلمات فقط) — درس مُوثَّق من التنفيذ. (المكوّن `WordReveal` يطبّق ذلك.)
6. **معرفات الشرائح فريدة وببادئة الفصل** (`ch1-`, `ch2-`…) لأن الخريطة والتنقل يعتمدان عليها.
7. **الاتجاه RTL** لكل النصوص العربية، و`ltr` للمعرّفات والكود.

> القواعد 1 و6 (وغيرها) تُفحص آلياً بـ `validatePresentation()` في `src/lib/validate.ts`؛ النتيجة تُطبع في وحدة تحكم المتصفح أثناء التطوير وتُختبر في `npm test`.

## 10. قائمة تحقق الهيكل (Definition of Done)

- [ ] 3–5 فصول، كل فصل يبدأ «تمهيد» وينتهي «خلاصة»
- [ ] 4–8 شرائح لكل فصل، كل شريحة نمط واحد من العشرة
- [ ] شاشة العنوان مكتملة (جهة، نوع عمل، عنوان، منجزون، تاريخ، زر بدء)
- [ ] المقدمة 3–4 خطوات (سياق ← إشكالية كسؤال ← أهداف)
- [ ] الخاتمة تلخّص فقط
- [ ] كل `slide.id` فريد و`chapterId` صحيح
- [ ] التدفق يعمل كاملاً: عنوان ← مقدمة ← خريطة ← شرائح ← خاتمة
- [ ] التحكم: أسهم + Esc + شريط تقدّم + عدّاد

للتحقق الآلي من البنود الستة الأولى: `npm run check` (فحص أنواع + اختبارات + بناء). ولا يُعدّ العرض مكتملاً ما دام التحقق يحذّر من شرائح `placeholder`.

## ملحق: طبقة الحركة (Animation Layer)

القالب يأتي بعدّة حركة مثبتة مسبقاً حتى لا يحتاج الوكيل إلى تثبيت شيء: `framer-motion` (الأساس)، `gsap` + `@gsap/react` (تسلسلات معقّدة، SplitText بالكلمات)، `canvas-confetti`، `tsParticles`، `lottie-react`، `react-type-animation`، `rough-notation`، `react-parallax-tilt`، `@formkit/auto-animate`، `tw-animate-css`. لكل منها مغلّف في `src/components/effects/`، ومفتاحان في البيانات: `meta.background` (خلفية جسيمات لشاشة العنوان) و`final.celebrate` (قصاصات الخاتمة).

قاعدة الاختيار: **مؤثر واحد مهيمن لكل شريحة**، والقاعدة §9.5 سارية على كل المكتبات (كلمات لا حروف). جدول القرار والأمثلة: [`ANIMATION_LIBRARIES.md`](ANIMATION_LIBRARIES.md).

---

**خلاصة الوكيل في سطر**: *خذ مشروعك، استخرج 3–5 أسئلة = فصول، قسّم كل فصل إلى 4–8 محاور، صنّف كل محور بنمط من الأنماط العشرة، ضعه في عقد `SlideData`، أضف الشاشات الخمس الثابتة — ويصبح جاهزاً كأي قالب عرض تقديمي متكامل.*
