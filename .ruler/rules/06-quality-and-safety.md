# الجودة والسلامة

## الحدود والتحقق

- لا تعدّل `src/components/` أو `src/hooks/` أو `src/lib/` لمجرد تعبئة بيانات عرض؛ حافظ على نطاق التغيير واختبر أي تعديل بنيوي.
- شغّل `npm run check` قبل التسليم، وأصلح أخطاء الأنواع والاختبارات والبناء.
- عند تعديل عرض فعلي، افحص تقرير التحقق في وحدة تحكم المتصفح: يجب ألا تبقى تحذيرات `slide.blank` أو `preface.blank` أو `chapter.title` أو `slide.placeholder` ولا نصوص نائبة في `src/data/`.
- القالب الأساسي أبيض عمداً. حافظ على اختبارات القالب الأبيض في `render.test.tsx`؛ إذا عُبئت بيانات `src/data/` لعرض حقيقي، حدّث مجموعة اختبار القالب كي تعمل على نسخة بيانات فارغة لا على العرض المعبّأ.
- تعريف الاكتمال: يمر `npm run check`؛ 3–5 فصول، لكل فصل تمهيد ومحاور وخلاصة؛ مقدمة 3–4 خطوات والإشكالية سؤال واحد؛ الخاتمة تلخص بلا جديد؛ لكل شريحة تكوين بصري متنوع ومؤثر مهيمن واحد على الأكثر؛ راجع مهارات `animation-qa` و`arabic-typography-motion`؛ الرسوم البيانية RTL، بعنوان خبري، ≤7 فئات ولون مميز واحد، وحمّل المكتبات الثقيلة كسولاً.

## الأصول وGit

- لا تضف أصولاً كبيرة أو غير مرتبطة إلى Git؛ تجنب فيديو أو Lottie ضخم (>1 MB) في المصدر، واستخدم المسارات والسياسات الموجودة.
- لا ترفع `image-search/` دون ضرورة ومراجعة؛ لا تتضمن نتائج خارجية غير موثوقة أو حساسة في التغيير.
- لا تستبدل أو تتخلص من تغييرات قائمة للمستخدم. قبل عمليات Git راجع `git status` و`git diff`، ولا تنشر ملفات مؤقتة أو حساسة أو غير مرتبطة.
- عند التعامل مع شعارات أو مصادر خارجية، لا تصف الأصل بأنه رسمي أو مرخّص دون سند واضح.

## أوامر

```bash
npm install          # تجهيز الاعتمادات
npm run dev          # معاينة محلية وتقرير تحقق في المتصفح
npm test             # اختبارات المشروع
npm run check        # فحص شامل: المكتبات + الأنواع + الاختبارات + البناء
npm run ai:rules     # توليد تعليمات الوكلاء من .ruler/
```
